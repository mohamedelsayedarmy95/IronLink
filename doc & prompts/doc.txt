### 1. 🛡️ IronShield — Intelligent Security Center

**Source:** ChatGPT, Qwen, Grok, Principal Engineer

**Concept:** A real-time security dashboard that monitors account health and provides actionable security insights — without exposing private content.

#### Core Capabilities

| Capability | Description | Privacy Boundary |
|------------|-------------|------------------|
| **Login Alerts** | New login from unknown device → user notified immediately | No message content |
| **Suspicious Activity** | Pattern anomalies → flagged for user review | No message content |
| **Session Management** | View all active sessions, remote logout any device | No message content |
| **Device Trust** | Trusted devices list with verification status | No message content |
| **Security Score** | Clear, actionable security rating (High/Medium/Low) | No message content |
| **Secure My Account** | One-click secure action (logout all, rotate keys, verify devices) | No message content |
| **Link Safety** | Suspicious link detection (phishing, malware, fake login pages) | No message content |
| **Scam Intelligence** | On-device detection of impersonation, fraud, payment scams | On-device only |

#### Implementation Notes

- All intelligence runs **on-device** — server never sees message content
- No E2EE content is ever sent to server for analysis
- Clear explanations for every alert ("Why am I seeing this?")
- Security Center is transparent and auditable

### 8. 📱 IronMesh — Off-Grid Communication

**Source:** ChatGPT, Qwen, Principal Engineer

**Concept:** Send messages via **Bluetooth Low Energy** and **Wi-Fi Direct** when internet is unavailable. Creates a local mesh network between nearby IronLink devices.

#### Use Cases

| Scenario | Description |
|----------|-------------|
| **Disasters** | Communication when cellular network is down |
| **Remote Areas** | No internet or cellular coverage |
| **Events** | Festivals, conferences, stadiums |
| **Travel** | Airplanes, underground |
| **Military/Field** | Operations without network infrastructure |

#### Technical Requirements

- Local device-to-device discovery
- E2EE for all mesh messages
- Queue and delivery once connected
- Battery-aware — not always scanning
- Fallback to internet when available

### 9. 🔥 IronFlow — Conversation Automation

**Source:** ChatGPT, Qwen

**Concept:** Let users create automation rules within conversations — **Trigger → Condition → Action** — without exposing E2EE content to the server.

#### Example Automations

```
WHEN new PDF received
IF contains "URGENT"
THEN → Alert me → Pin message → Add to Important
```

```
WHEN message contains "meeting" or "deadline"
IF from specific contact
THEN → Create Reminder → Add to Calendar
```

```
WHEN document uploaded
IF contains "Invoice" and amount > 10,000 EGP
THEN → Notify Finance team → Archive in Documents
```

#### Privacy Boundary

- All pattern matching runs **on-device**
- Server never sees rule conditions
- Actions are server-executed (but without knowing why)

### 12. 📱 IronMasks — Contextual Identities

**Source:** Principal Engineer, Qwen

**Concept:** One account, multiple **Masks** (identities). Work Mask, Family Mask, Community Mask — each with separate keys and isolation.

#### Mask Properties

| Property | Description |
|----------|-------------|
| **Username** | Unique per mask |
| **Avatar** | Different profile image |
| **Encryption Keys** | Separate keys per mask |
| **Conversations** | Isolated per mask |
| **Privacy Settings** | Per-mask settings |
| **Contacts** | Per-mask contacts |

#### Privacy Boundary

- Masks are **completely isolated** — if one mask is compromised, others remain safe
- Server sees only the active mask identity, not associated masks
- Users can switch masks seamlessly

### 17. 💀 IronLegacy — Digital Inheritance

**Source:** Principal Engineer, Qwen

**Concept:** What happens to encrypted data when the user passes away? No company can decrypt E2EE content.

#### Solution: Dead Man's Switch

| Mechanism | Description |
|-----------|-------------|
| **Inactivity Timer** | If user doesn't login for X days |
| **Trusted Contacts** | Pre-designated trusted contacts receive keys |
| **Shamir's Secret Sharing** | Split keys among multiple trusted contacts |
| **Limited Scope** | Only access specific archives/wallets |
| **Privacy-Preserving** | Contacts don't know what others received |

# ⚠️ EXECUTION GUARDRAILS (Per Engineering Prompt v3.0)

## Must Be True Before Implementing Any Feature

| Rule | Implementation |
|------|----------------|
| **Audit First** | Inspect current system before any change |
| **Evidence-Based** | All claims require evidence (paths, tests, metrics) |
| **Safe Change** | Follow: Inspect → Understand → Characterize → Test → Change → Validate → Observe → Document → Rollout → Monitor → Stabilize |
| **Definition of Done** | All 15 criteria must be met before marking complete |
| **Privacy by Default** | Never weaken E2EE or expose private content |
| **Feature Flags** | All medium/high-risk features require flags |
| **Rollback Plan** | Every change must be revertible |

## Anti-Patterns to Avoid

```
❌ Implement without auditing first
❌ Present mocked/demo work as production-ready
❌ Log sensitive data (messages, keys, OTPs, OCR content)
❌ Hardcode secrets or credentials
❌ Process E2EE content with AI without explicit user consent
❌ Claim encryption/security/compliance without evidence
❌ Fabricate test results, metrics, or guarantees
❌ Document planned work as completed work
```
